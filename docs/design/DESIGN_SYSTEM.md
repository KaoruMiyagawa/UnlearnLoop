# UnlearnLoop 设计系统

## 1. 设计原则

界面采用浅色、克制、内容优先的通用知识学习工具风格。学习者随时知道自己在哪个工作空间、当前要完成什么、系统为什么提出问题、下一步如何继续。引导式工作流应适配文本、代码、公式、图表或其他领域内容，而不是把界面固定成 Python 编辑器。页面不是聊天记录，不使用装饰性渐变、发光效果或无意义卡片堆叠。

视觉参考 [VibeHub](https://vibe-hub.org/) 的清爽信息组织感，仅作为方向参考，不复制其布局或品牌资产。

## 2. 视觉基础

### 2.1 颜色令牌

令牌应在前端统一定义，组件不得散落直接使用十六进制颜色。

| 用途 | 令牌 | 建议值 |
|---|---|---|
| 页面背景 | `surface-page` | `#F7F8FA` |
| 内容背景 | `surface-raised` | `#FFFFFF` |
| 次级背景 | `surface-subtle` | `#F0F2F5` |
| 主文字 | `text-primary` | `#1F2937` |
| 次级文字 | `text-secondary` | `#667085` |
| 边框 | `border-default` | `#E4E7EC` |
| 主操作 | `action-primary` | `#2563EB` |
| 主操作悬停 | `action-primary-hover` | `#1D4ED8` |
| 正向反馈 | `feedback-success` | `#15803D` |
| 警示/不确定 | `feedback-warning` | `#B45309` |
| 错误 | `feedback-error` | `#B42318` |
| 信息辅助 | `feedback-info` | `#475467` |

颜色必须同时配合文字、图标或状态标签，不得只用颜色传递诊断状态。正文和背景需满足可读性对比要求。

### 2.2 字体与排版

默认使用系统无衬线字体栈，中文优先 `-apple-system, BlinkMacSystemFont, "Segoe UI", "PingFang SC", "Microsoft YaHei", sans-serif`。正文 16px、行高 1.6；辅助文字 14px、行高 1.5；页面标题 28/36px；区块标题 20/28px；小标签 12/16px。标题使用 600，正文使用 400，避免全页粗体。

### 2.3 间距、圆角与阴影

采用 4px 基础单位：`space-1=4`、`2=8`、`3=12`、`4=16`、`5=20`、`6=24`、`8=32`、`10=40`、`12=48`。页面主列最大宽度 1200px，阅读内容最大宽度 760px。控件高度优先 40px 或 44px，圆角 8px；内容区仅使用轻边框或极浅阴影。

## 3. 全局结构与组件

### 3.1 导航

桌面端使用顶部品牌区 + 左侧主导航，入口固定为“首页、学习、诊断、复习、学习档案”；当前入口有文字和背景状态。移动端使用顶部标题和可展开导航，不把所有入口压缩成小图标。导航不承担业务状态显示，未保存会话通过明确提示表达。

### 3.2 按钮

主按钮用于当前页面唯一主要动作；次按钮用于并列但低风险动作；文字按钮用于取消、返回或辅助链接；危险按钮需要确认。按钮必须有 hover、focus、disabled、loading 状态，loading 时保留宽度并禁止重复提交。文案使用动作 + 对象，如“提交答案”“开始诊断”“安排复习”。

### 3.3 表单与答案输入

标签始终可见，不依赖 placeholder。输入框提供 focus 边框、校验提示和字符/代码上下文。代码输入区使用等宽字体、语言标识和纯文本编辑能力；第一阶段不默认提供不安全的代码执行按钮。提交前保留答案草稿，失败后可重试而不清空内容。

### 3.4 反馈、状态与证据

Toast 只用于短暂的非关键确认；关键诊断结论必须在页面内持久呈现。状态标签使用“待处理、需要证据、进行中、已确认、已降低、已排除、已完成、失败”等受控文案。证据行显示来源、时间和摘要；模型生成内容与系统规则结果通过来源标签区分。

## 4. 页面布局与交互

### 4.1 首页

首页由一句产品定位、主行动“开始学习”、最近学习状态和待复习摘要组成。首屏不放长营销文案或聊天框；没有历史时显示三步说明：选择知识点、回答问题、验证掌握。最近状态以简洁列表呈现，点击进入对应工作空间。

### 4.2 学习工作区

桌面采用三段结构：顶部会话进度与知识点；中央材料/题目/答案区域；右侧窄栏显示“本题目标、已收集证据、下一步”。中央内容根据知识包切换文字、代码、公式、图表或其他输入形式，但外层流程保持一致。移动端改为单列，右侧信息变为可展开底部区块。提交后先展示评估摘要，再提供“查看可能原因”和“继续诊断”，不铺满模型原文。

### 4.3 错误诊断中心

诊断中心以“当前判断”开头：问题摘要、候选错误原因列表、每个原因的置信度和支持/缺失证据。下方是当前诊断问题及其目的，再下方是决策时间线。候选原因允许并列，不强制排序为唯一真相；回答后突出显示哪些原因被支持、降低或排除，以及选择下一步的理由。

### 4.4 复习历史

左侧为筛选和排序，主区为按时间排列的学习事件；每条记录显示知识点、错误模式、最近验证结果和下次复习时间。打开详情先展示错误摘要和证据，再提供开始变式题按钮。无历史时解释如何产生第一条记录，不展示空白表格。

### 4.5 学习档案

学习档案展示知识点状态概览、近期趋势、待确认错误模式和学习设置。状态使用“稳定、需要练习、需要诊断、证据不足”等可解释标签，不展示未经验证的精确能力百分比。详情页能进入关联证据和复习计划；用户可以查看并删除自己的学习数据。

## 5. 响应式规则

断点按内容而非设备命名：窄屏 <640px 单列；中屏 640–1023px 折叠辅助栏；宽屏 ≥1024px 展开导航和双栏内容；≥1280px 扩展主列留白而不无限拉宽。移动端主要动作固定在内容末端或安全底部区域，不能遮挡输入。表格改为信息块，时间线保持从上到下阅读，焦点顺序与视觉顺序一致。

## 6. 页面状态规范

- 加载：使用结构相近的 skeleton 或明确“正在加载…”，提交中的按钮锁定。
- 空数据：说明为什么为空，并提供唯一主要行动，例如“开始第一场学习”。
- 错误：说明影响范围、是否已保存、重试动作和替代路径；模型失败不显示伪造结论。
- 成功：说明完成了什么、产生了什么记录、下一步是什么。
- 不确定：说明证据不足，允许继续追问或稍后复习。
- 离开/恢复：有未提交答案时提示保留草稿或放弃；恢复时显示上次阶段。

## 7. 可访问性与评审门槛

所有控件支持键盘操作、可见焦点和语义标签；错误提示与输入关联；图标不独立承载文字意义；长内容可缩放。视觉评审至少检查桌面宽屏、平板、手机、加载/空/错误/成功状态，以及诊断不确定性和证据时间线是否易读。视觉方案通过评审后，才能开始前端页面实现。
