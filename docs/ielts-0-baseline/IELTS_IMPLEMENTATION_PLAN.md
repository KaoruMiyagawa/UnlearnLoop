# IELTS 实施顺序与验收计划

状态：评审草案；基线 `03ed2270005956d3bce5f713c4ca03bd0f119590`。IELTS-0 是规划，I1–I7 均为未来开发阶段。目标是每个实现阶段都有可运行、可暂停的产品切片，不把后续能力写成现有能力。

## 1. 执行原则和依赖

```text
IELTS-0 规划/评审
    ↓
I1 Academic 阅读薄切片 + 安全迁移 + 引擎适配
    ↓
I2 Academic 阅读题型 + 英语基础词汇
    ↓
I3 听力题型与音频播放
    ↓
I4 写作工作区和多维反馈
    ↓
I5 口语录音、转写和多维反馈
    ↓
I6 Academic 四科模拟、计划与证据档案
    ↓
I7 General Training 差异与整卷
```

I4 的文本评价可在 I3 稳定后独立安排，I5 依赖 I3 的媒体权限与 I4 的多维评价记录；I6 依赖四科的版本化内容和提交能力。是否开放分数估计是独立质量门禁，不阻塞用户保存作答或获得明确标注来源的定性反馈。

跨阶段前置：继续解决 [现有 MVP 审查](MVP_FINAL_AUDIT.md) 的 Vite 依赖、Python 安全扫描、备份恢复、数据导出/删除和运行验收；实际范围与优先级由负责人批准。所有已通过的 Python 流程是回归基线；任何阶段都不得删除 Python 内容包、历史迁移和审查报告。

## 2. IELTS-0：方向、题型与架构评审（本次）

- **交付**：四份 IELTS 规划文档；Academic 为主线、GT 为后续扩展；题型矩阵与现有引擎/数据库迁移方案。
- **可运行基线**：现有 Python 学习闭环仍可运行；本阶段不声称有 IELTS 题目或新网站功能。
- **验收**：负责人确认产品定位、I1 切片、内容授权与隐私边界；所有待确认事项有决策记录后进入 I1。

## 3. I1：Academic 阅读薄切片与迁移安全

- **可运行成果**：本机用户选择原创 Academic 阅读材料，完成单选与 True/False/Not Given，查看客观结果、竞争性原因与一个追问，完成不同文章中的验证并安排复习。Fake Agent 决策始终标注模拟；无可用题时明确提示。
- **交付**：最小题组/题目版本、单选/三值作答、客观题评价器、证据适配、受控 API/Focus 呈现、经审校的原创示例内容。先实现数据库备份/恢复保护及面向本地用户的数据导出和删除策略；单用户仍只监听 loopback。
- **依赖**：迁移计划评审；版权来源及编辑；新增领域评价与 Python 评价器并存。提供新 API 时保留 v1 Python 行为。
- **最低验收**：至少三篇独立原创文章分别支持初练、验证和复习，覆盖单选、T/F/NG 正确/错误/未给出；每题有审核过的答案与来源锚点。一次正确不能变成长期保持；同键同载荷重试不重复写入，异载荷冲突；服务重启和刷新可恢复；不存在标准答案提前泄露。
- **测试**：Python 原有全量回归；迁移前后 0003 副本与备份恢复；SQLite 外键/事务；不同类型/边界作答、并发、无题、诊断证据不足、复习到期及 API/浏览器错误恢复。所有写入使用隔离数据库。

## 4. I2：Academic 阅读覆盖与词汇基础

- **可运行成果**：用户完成 Academic 阅读全部矩阵类型，以及关联语境词汇训练；每题可查看经审核的答案依据和个人薄弱点。
- **交付**：匹配、选择、多空、简答与图示标签控件；选择复用规则、单词/数字上限、审核过的接受答案与版本化规则；R1–R11 内容和错误类型；词义、同义改写、搭配练习。
- **最低验收**：矩阵每个 R1–R11 类型至少 1 个已审校可运行题组，包含该类型正常/错误/边界样例；建立不少于 3 篇可独立用于练习、验证、复习的材料。多空逐项分数、重复选项、超词数、拼写和答案变体均有确定结果；图示有文本替代。
- **测试**：评价器表驱动边界测试、题目版本和素材变更回放、独立性组过滤、迁移与无题回退、键盘/窄屏和真实 API 流程。此阶段不输出官方或未校准的阅读 band。

## 5. I3：听力与音频播放

- **可运行成果**：用户播放带许可的原创听力素材，完成四部分及 L1–L6 交互，查看逐题结果、证据位置并复习。练习可重听；模拟单次播放仅在所选规则允许下实施。
- **交付**：媒体元数据和私有存储、音频播放器、题组时间锚点、许可检查、听力所有矩阵题型；音频失效/解码失败处理及加载状态。
- **最低验收**：覆盖 Part 1–4、L1–L6 每类至少 1 个经审校示例；初练、迁移和复习分别使用独立材料。音频不可用不提交空结果，练习/模拟模式的播放权限与记录独立；地图/图示提供替代文本。
- **测试**：音频格式、时长、哈希、异常/网络中断；逐空与字数规则；播放恢复、模考一次播放策略、可访问性与手机布局。浏览器端限制不宣称防作弊。

## 6. I4：写作与英语表达

- **可运行成果**：用户完成 Academic Task 1 图表/流程题或 Task 2 作文，保存长文本草稿、提交并查看明确来源的四维反馈。无可信评价时可保留作品并显示待人工评价或证据不足。
- **交付**：长文本 response、题图及文本替代、Task 1/2 rubric 版本、写作 evaluator 接口、分维证据锚点、语法/词汇/表达练习。首版可用人工审校样例或标注清楚的 Fake 结果演示接口；Fake 反馈不计入真实能力证据。
- **最低验收**：至少一个 Task 1 图表、一个流程/图示和一个 Task 2 原创任务；四维反馈锚点可回到原文，Task 1/2 第一维区分正确；空文、短文、离题、未知图表、超时及无效结构输出均能安全处理。Task 2 权重和字数提示可配置，但不因为字数达标就判满分。
- **测试**：响应长度、Unicode 偏移与版本一致性、隐私/日志脱敏、异步失败后保留原文、幂等和重复收费防护；专家标注集作为未来校准基础。未校准前不得显示 AI band。

## 7. I5：口语录音与反馈

- **可运行成果**：用户完成 Speaking Part 1–3 样例，录制、试听、保存并在有授权服务时获取转写及基于证据的反馈；不具备条件的维度明确弃评。
- **交付**：录音权限和中断处理、私有媒体资产、转写适配器、说话轮次/时间戳、口语评价协议、独立同意与成本预算、录音及派生数据导出/删除。
- **最低验收**：每个 Part 至少 1 套原创样例；录音可在刷新后按服务端状态恢复，拒绝权限/低音量/噪声/断网均有明确处理。没有音频能力时发音维度为证据不足；只用转写不能判发音。Fake 转写/反馈明确标识，不能用于宣称真实口语能力。
- **测试**：格式/时长/大小校验、上传中断和幂等、媒体归属、删除及备份策略、时间戳与转写纠正、预算和授权开关、 provider 失败和隐私脱敏；真实语音 provider 只在后续明确授权后单独验收。

## 8. I6：Academic 四科模拟、计划和档案

- **可运行成果**：用户使用完整原创 Academic 模拟卷完成四科，查看已完成的原始结果、非官方反馈、学习档案和后续计划。支持模拟中断后的明确恢复政策。
- **交付**：版本化 ExamBlueprint/ExamRun、题组排序、服务端时间记录、模考提交/锁定、模拟与练习数据标记、每周计划、四科证据视图、复习入口及数据控制。
- **最低验收**：至少 1 套审校完整模拟卷：听力 4 部分/40 题、Academic 阅读 3 篇/40 题、写作 Task 1/2 和口语 Part 1–3；素材授权记录完整。阅读/写作 60 分钟及听力/口语时序以所选考试规则版本和官方资料复核；地区及交付方式差异由版本配置处理。提交前不泄露答案/诊断；缺科不得生成 Overall。
- **估分门禁**：听/读只展示原始分及题卷信息，除非有可审计、经认可的该模拟卷转换依据；写/说只有在盲测、评分者一致性、不同口音和文本质量偏差评估达到负责人预先批准的阈值后，才能显示带范围的非官方估计。Overall 必须基于四个足够可信且可比的科目估计、版本化规则与明确不确定性；不得以预估值保证 Band 8。
- **测试**：整卷计时边界、暂停/网络断线、未完成科目、延迟模型结果、重复提交、计划解释、时区和复习到期、重启恢复、个人导出删除、桌面与 390px 窄屏。浏览器脚本与 API 测试需在隔离库下执行。

## 9. I7：General Training 扩展

- **可运行成果**：用户可选择 GT，完成生活/工作场景阅读、Task 1 书信与 Task 2 议论文，以及共用听力/口语，并完成标注为模拟的 GT 整卷。
- **交付**：GT 题组、答案/评分版本、书信工作区、模式切换、GT 单独的阅读估分校准配置和档案筛选。
- **最低验收**：GT 阅读矩阵相关题型每种至少 1 个原创审校题组；有书信与 Task 2 样例以及完整 GT 模拟卷。Academic/GT 的阅读/写作内容和转换依据不混用，听说素材可以依法共用。
- **测试**：两考试版本切换、题组归属、不同材料与评分规则、历史筛选和迁移/复习隔离；继续执行全部 Python 与 Academic 回归。

## 10. 公共质量门槛

每阶段完成前执行：

1. 后端 pytest、前端测试、TypeScript typecheck、production build、迁移链和 `git diff --check`；所有数据库写测试使用临时隔离库。
2. 真实 HTTP 测试覆盖成功、错误、服务重启、幂等和无题；用户能看见真实服务端结果。涉及 UI 时补浏览器桌面、窄屏、键盘和断网恢复验收；受环境阻止就标记未完成。
3. 默认 `ALLOW_REMOTE_MODEL_CALLS=false`；测试用 Fake providers，绝不把 Fake 结果标成真实模型。真实文本/ASR/音频调用要单独获得授权和预算。
4. 新数据模型、规则、题目和评估器有版本；旧 Python 记录可查询且结果不改变；标准答案、密钥、私人音频和原始模型提示不进入公开题面或 Git。
5. 内容质量由编辑核对授权、答案与证据锚点；主观评分由具备资质的人工标注者独立评审。所有预估分数有版本、样本与适用范围，证据不足允许弃评。

## 11. 规模、成本与待定事项

- 这是依赖顺序而非时间承诺。每阶段工作量取决于内容编辑、媒体授权、专家评分和测试环境；在完成 I1 细化前不承诺日期。
- 预算设计按 `文本输入/输出 token × 单价 + 转写分钟 × 单价 + 音频评价分钟 × 单价 + 存储/人工审校` 估算；供应商、价格、每次/每日额度均待确认，不以猜测价格当承诺。
- 每次评价须提供预计消耗或预算上限；超额时暂停、保留作答，可选择本地规则或之后重试。付费请求的超时恢复先查询 provider/本地任务状态，避免重复费用与重复评价。
- 带真实模型的评分校准需要事先确定标注协议、样本量、盲测拆分、可接受误差与偏差阈值；模型、提示词或评分细则变更后重新评审。没有这些证据就不能推出 Band 8 达标概率。
