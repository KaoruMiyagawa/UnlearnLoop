## 当前质量基线

IELTS Reading 已有 Academic / General Training 的部分 TFNG 与 Matching Headings 流程，以及诊断、定向训练、独立迁移、首轮延迟复习、学习记录和双主题前端。

**IELTS-2B.1 Phase 6.2 最终工程验收为 PASS WITH LIMITATIONS。** 证据有效性登记、状态协调与重新验证已通过隔离复验。实际部署库仍需逐库审查，正式内容与生产发布仍需独立验收。原 Phase 6 FAIL 作为历史记录保留。[最终复验](IELTS_2B1_PHASE6_2_ACCEPTANCE.md) · [原 Phase 6 报告](IELTS_2B1_FINAL_ACCEPTANCE.md)

## 优先级

### P0 — Learn 四项技能入口与首个真实练习

- 顶层产品结构为 Learn / Discover / Adapt。Discover 规划合法外部资源，Adapt 规划个性化决策。
- Learn 提供 Listening / Speaking / Reading / Writing。Reading 复用真实工作区，Listening 和 Writing 各有一套有限原创练习，Speaking 提供规划详情。
- 验收覆盖双主题、桌面与手机视口、键盘与触控，以及 Reading 的实际会话和首轮复习回归。

### P1 — 跟进 Phase 6.2 复验限制

- 对实际部署库进行只读影响扫描，核查来源不明的历史版本与记录。
- 对修订版 Reading 材料、标题和答案依据进行独立编辑审校。
- 继续验证多轮间隔复习及生产发布条件。

### P2 — 统一语言能力模型与初始评估

- 定义可解释的听、说、读、写及词汇、语法、理解、表达能力维度。
- 为能力证据、来源、更新时间、可信级别和未知状态建立共同模型。
- 设计初始评估及持续更新方法，避免把 IELTS 目标分数当作当前能力。
- 验收：每项能力结论可追溯；未测状态保留未知；不同评价来源不混淆；无未校准的 Band 预测。

### P3 — 个性化学习计划与学习 Agent 策略

- 结合目标、能力证据、时间和内容可用性安排下一步活动。
- 让 Agent 给出可审查的行动、理由、目标能力、证据需求和降级结果。
- 复用现有会话、作答、诊断和复习能力，不以自由文本回答代替服务端业务状态。
- 验收：规划建议有来源和不确定性；无合法内容时安全降级；规则、Fake 与真实模型来源清楚区分。

### P4 — 逐步扩展 Listening、Writing、Speaking

- 在内容版权、个人数据、录音/媒体处理、人工校准和评估标准明确后分技能建设。
- 听力第一套有限原创练习已交付，包含合成音频、服务端评分、复盘时间锚点和共享学习历史。Writing 已交付一套原创 Task 2 练习，包含草稿恢复、基础文本检测和修订版本。后续写作语义反馈需要单独验证。口语计划建立同意流程、录音与轮次证据。
- 验收：每项评价有可核查证据或明确弃评；AI 结果标为非官方；隐私与恢复流程通过专项验证。

### P5 — 词汇、语法、表达与真实语言运用

- 建立与实际阅读、听力、写作和口语表现关联的词汇、语法、理解和表达练习。
- 逐步加入现实沟通任务，避免只有离散题目正确率。
- 验收：练习由能力证据和计划驱动，任务与答案/评价规则版本化，并提供真实语境反馈。

### P6 — 长期记忆、跨技能迁移与自适应决策

- 扩展多轮间隔复习，明确遗忘、成功、失败和过期证据的状态语义。
- 验证跨材料、跨任务及跨技能迁移，区分即时表现与长期保持。
- 使用学习结果评估 Agent 策略，不将启发式权重描述为统计概率。
- 验收：迁移和复习材料独立、来源可追溯、重试幂等，并有足够的纵向验证数据。

### P7 — 其他语言及更完整的智能教学能力

- 将语言共用的学习与证据模型，与特定语言的文字、语音、内容和评价规则分层。
- 只有在内容、模型评测、隐私、成本和运营能力满足后，才逐步增加其他语言与更先进的教学策略。
- 验收：每种新语言具备独立内容和质量评估；不得把英语或 IELTS 的假设未经验证地直接迁移。

- `IELTS_IMPLEMENTATION_PLAN.md` 及 `docs/ielts-0-baseline/`、`docs/archive/` 保留早期 IELTS 阶段拆分与原始记录。它们用于追溯当时计划，不覆盖本路线图的当前产品优先级，也不表示对应功能已交付。
- UKVI、Life Skills、Mock Tests 和其他语言均未交付完整学习流程。

## 通用质量门禁

- 产品文案、前端状态和 API 语义必须区分已实现、部分实现、有质量阻断、规划中及未实现。
- 新增/修改数据库结构须使用增量 Alembic 迁移，并在隔离 SQLite 验证旧数据与升级/恢复路径。
- API 需验证权限边界、版本固定、幂等、并发、超时及刷新恢复；`learner_id` 在认证前不能当作身份验证。
- 运行相关后端和前端测试、类型检查、Production build、迁移唯一 head 检查和 `git diff --check`。
- 浏览器验收应连接隔离服务和数据库。使用规则或 FakeModelProvider 时，不能声称已验证真实 AI 教学质量。
- 内容须记录原创/许可来源、版本和答案依据；内部审核不能代替独立编辑或 IELTS 专家审校。
