# UnlearnLoop 开发路线图

> 本文保留早期规划，规划项不等于已交付；当前 main 的状态见 [README](../../README.md)，IELTS-1 在独立开发分支，尚未合并。

路线图按“先确定行为，再实现界面和基础设施”的顺序排列。阶段完成以验收标准为准，而不是文件数量或模型调用成功为准。

## 阶段 0：规划与视觉评审

交付物：PRD、设计系统、架构文档、路线图、README；一次产品范围评审；一次首页/学习/诊断/复习/档案视觉方案评审。

依赖：无。

验收：核心术语、状态名称、第一阶段边界和 API/实体方向在文档间一致；视觉评审覆盖桌面、移动、加载、空、错误、成功和不确定状态；产品负责人确认待确认问题。

需要学习：REST API 资源建模、FastAPI/React 项目边界、基础可访问性、诊断式学习基本概念。

## 阶段 1：仓库骨架与开发质量基线

交付物：前后端最小启动骨架、配置样例、环境变量说明、代码格式和 lint/typecheck、pytest 与前端测试命令、CI 草案；不实现完整业务。

依赖：阶段 0 完成。

验收：新开发者按 README 可启动前后端；健康检查可用；无密钥进入仓库；本地和 CI 可执行质量检查；目录职责与架构一致。

需要学习：Vite/TypeScript 配置、FastAPI 依赖注入、pytest fixtures、SQLAlchemy 2.x 基础和 GitHub Actions。

## 阶段 2：领域模型、迁移与静态内容

交付物：知识领域、知识点、材料、题目、会话、作答、证据、假设、决策事件、复习项等最小模型；SQLAlchemy 映射和第一版迁移；Python 首个内容包；领域状态转移。

依赖：阶段 1。

验收：可从空数据库运行迁移和种子；外键关系与状态约束可测试；固定案例能用一个内容包创建会话、保存答案、追加证据和重建诊断时间线；重复事件不会破坏数据；核心状态流程不出现 Python 专属字段。

需要学习：Alembic 迁移策略、事务边界、幂等键、领域事件与派生状态的区别。

## 阶段 3：模型服务与诊断决策内核

交付物：`ModelProvider` 协议、DeepSeek 适配器、假 provider、结构化输出 schema、错误映射、诊断追问选择和干预决策器、脱敏模型调用记录。

依赖：阶段 2；真实远程调用前确认隐私与预算。

验收：无真实网络时可用 fixture 重放完整决策；无效 JSON、超时、配额和服务错误都有明确状态；候选假设能并列保留；固定输入下决策稳定；每次决策能回溯证据和理由。

需要学习：DeepSeek API 约束、结构化输出校验、重试/超时/限流、提示版本管理和 AI 评估样本设计。

## 阶段 4：后端 API 与第一条闭环

交付物：主题/会话/作答/诊断/干预/迁移/复习/知识状态 API；统一错误响应；API contract 测试；本地 SQLite 端到端流程。

依赖：阶段 3。

验收：通过 API 可完成“选择知识点 → 提交答案 → 诊断追问 → 干预 → 迁移验证 → 更新复习”的流程；关键写操作幂等；模型不可用时答案和证据保留；API 文档与实际 schema 一致。

需要学习：FastAPI schema、HTTP 错误设计、SQLAlchemy session 生命周期、contract testing 和 API 版本化。

## 阶段 5：前端设计系统与核心工作空间

交付物：按阶段 0 评审结果实现设计令牌、导航、按钮、表单、反馈和响应式布局；首页、学习工作区、诊断中心最小可用界面。

依赖：阶段 4 API contract 稳定，且视觉评审已通过。

验收：用户可通过界面完成第一条闭环；桌面和移动布局符合设计系统；加载、空、错误、成功、不确定和离开恢复状态可验证；键盘操作和焦点顺序通过检查；不呈现为普通聊天页面。

需要学习：React 状态管理边界、表单草稿与异步状态、Tailwind 令牌、响应式布局和前端可访问性测试。

## 阶段 6：复习、档案与回归质量

交付物：复习历史、学习档案、数据删除/隐私设置、决策时间线；代表性诊断 fixture 集；端到端测试和可观测性最小日志。

依赖：阶段 5。

验收：用户能解释一条错误历史为何进入复习；迁移结果能更新状态；删除操作覆盖定义范围；关键路径端到端测试稳定；测试失败不依赖真实模型或网络。

需要学习：Playwright 或等效前端自动化、测试数据设计、可观测性字段、隐私删除和回归样本维护。

## 阶段 7：发布准备与有限试用

交付物：贡献指南、行为准则、问题模板、环境变量文档、架构决策记录、CI 必需检查、发布说明；小范围人工试用方案。

依赖：阶段 6；完成安全和隐私评审。

验收：干净环境可复现安装/运行；CI 阻止类型、测试、构建和规范回归；README 不夸大能力；试用反馈可映射到 issue；无未处理的高风险密钥、日志或代码执行问题。

需要学习：开源项目治理、GitHub Actions 缓存与矩阵、语义化版本、问题模板和基础威胁建模。

## 跨阶段测试方案

- 单元测试：领域状态、证据更新、候选假设和动作选择，优先纯逻辑。
- 集成测试：SQLAlchemy + SQLite 事务、迁移、仓储与 FastAPI 端点。
- 模型 contract 测试：假 provider、结构化输出边界、超时和重试，不依赖外部网络。
- 前端自动化：核心学习闭环、诊断分支、复习恢复、空/错/成功状态和键盘导航。
- 回放回归：固定输入、模型响应和决策事件，验证提示版本或规则修改没有悄然改变关键分支。
- 人工评审：候选原因是否有证据、追问是否真的区分、迁移题是否改变表面形式、文案是否明确不确定性。

## 阶段依赖总览

`规划/视觉评审 → 工程基线 → 数据与领域状态 → 模型与决策内核 → 后端 API → 前端工作空间 → 复习与档案 → 发布准备`

任何阶段若发现产品状态、证据结构或模型边界变化，应先更新相应文档和测试 fixture，再继续编码。
